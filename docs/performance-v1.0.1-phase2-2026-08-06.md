# V1.0.1 阶段 2 批量写入拆分验收

本轮把批量写入的分片、事务、连接、回执和结果整理从一个大类中拆开，同时保持原有公开入口和事务语义。
验证不连接真实数据库；H2 内嵌测试用于覆盖可执行集成路径，真实数据库吞吐、连接池和 P95/P99 仍留到最终认证。

## 结构结果

- `R2dbcBatchWriter` 从 1111 行收敛为 59 行门面，只负责组装协作者和分派写入模式。
- `R2dbcAtomicBatchWriter` 负责 ATOMIC 的 begin、commit、rollback、取消和 `UNKNOWN` 状态，272 行。
- `R2dbcIndependentBatchWriter` 负责 INDEPENDENT 的有界并发与逐分片事务，218 行。
- 分片消费、连接生命周期、结果整理、回执和恢复分别放入独立包内协作者。
- 本轮新增生产类型均低于 300 行，没有用空转发层或重复同步/响应式实现凑拆分结果。

## 行为验证

共运行 98 个聚焦测试，全部通过，覆盖：

- ATOMIC 整批提交、失败回滚、提交结果不确定和恢复令牌；
- INDEPENDENT 逐分片提交、冲突、失败、原始位置和汇总结果；
- 取消时的回滚、连接关闭或物理失效；
- 回执预留、重复请求恢复、摘要不匹配和 `UNKNOWN` 查询；
- 输入行数、结果分片数、缓存字节数、超时和观测事件；
- H2 R2DBC 内嵌集成路径。

core/rdb Checkstyle 同时通过，违规数为 0。

## 分配短测

环境为 Oracle JDK 21.0.10、JMH 1.37、单线程、1 fork、1 次 1 秒预热和 2 次 1 秒测量，启用 GC profiler。

| 场景 | 吞吐 | 每次操作分配 |
| --- | ---: | ---: |
| 单行 INSERT 计划 | 271.581 ops/ms | 9760.025 B/op |
| 单行 UPSERT 计划 | 215.846 ops/ms | 13816.032 B/op |
| 64 行 INSERT 参数布局 | 16.105 ops/ms | 115328.428 B/op |
| 64 行 UPSERT 参数布局 | 16.684 ops/ms | 114288.414 B/op |

原始结果见 [JMH JSON](performance-results/2026-08-06-v101-phase2-batch-plan.json)。这组短测验证批量计划和参数布局
入口能够稳定运行并给出后续可比较的分配快照，不直接经过 `R2dbcBatchWriter` 的连接与事务协调，因此不把它写成
数据库批量吞吐结论，也不替代最终真实库认证。

## 结论

阶段 2 已完成。批量写入的公开用法、流式有界消费、ATOMIC、INDEPENDENT、取消、回执和 `UNKNOWN` 语义保持不变，
原来的大类已经收敛为小门面，独立职责都能单独阅读和验证。
