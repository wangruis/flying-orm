# v1.0.0 源码发布检查清单

这份清单记录 `v1.0.0` 源码发布状态。代码存在、测试入口存在和真实环境验证通过是三件事，必须分别记录。

## API 与边界

- [x] 已生成 `flying-orm-core` 与 `flying-orm-rdb` 的 V1.0.0 公开 API 基线，并用精确字节码签名对比阻止未审查的新增、删除和签名变化。
- [x] `FlyingOrmClients.Builder` 是唯一统一组装入口；连接工厂和自定义执行器分别有明确的 Builder 起点。
- [x] 同步入口统一使用 `Sync*` 命名并桥接 R2DBC，不维护 JDBC 双内核或早期命名别名。
- [x] 批量请求统一为 `BatchWriteRequest`，不存在只返回总行数的第二套批量执行契约。
- [x] 普通 SQL 与批量分别使用类型安全的默认保护，批量默认保持 ATOMIC，单次显式配置优先。
- [x] 主项目保持零 Spring 依赖，方言可从 `ConnectionFactory` 自动识别。
- [x] 已复核核心公开类型的 Javadoc、命名、不可变性和线程安全说明；统一入口、错误报告、Scope、数据库异常以及 form/repository/schema/mapping/operator 边界已经完成多轮校对。
- [x] 列出计划在 1.x 保持稳定的公开包；执行包装器、数据库专用元数据 reader 和内部 `MappingPlan` 已收回包内。
- [x] 已清理本轮涉及代码中的无用 import、无用变量和重复校验；内部 `MappingPlan`、Schema 锁超时实现枚举等协作类型已收回包内。

## 正确性与安全

- [x] 前端结构化条件不接受 SQL，值全部参数绑定。
- [x] Tenant/Data/Field/Time Scope 与逻辑删除可安全 AND，写入有租户和字段保护。
- [x] 普通查询、更新和连接获取使用 `SqlExecutionOptions`；批量使用带分片、模式和并发边界的 `BatchWriteOptions`。
- [x] 已完成并归档 MySQL、PostgreSQL/pgvector、H2、Oracle、SQL Server 的真实库认证，详细版本、场景和证据目录见 `database-certification-2026-08-02-latest.md`。
- [x] Oracle Free 23.26.0 和 SQL Server 2022 CU22 GDR1 已完成三轮预览真实库认证；功能、LOB、元数据、批量事务、池耗尽恢复、慢消费者取消、持续并发、死锁、显式锁超时、会话终止和 UNKNOWN 恢复均已通过。
- [x] testkit 完成批量 UNKNOWN、取消、连接中断、死锁和锁超时的确定性故障注入。
- [x] 四库目标驱动故障边界已经完成；Oracle/SQL Server 的死锁、显式锁超时、断链和 UNKNOWN 均已实库通过。SQL Server 连接关闭 dropped 日志不影响业务结果，作为正式支持下的已知驱动日志边界继续跟踪。

## 性能与并发

- [x] JMH 已覆盖条件、渲染、映射、缓存、批量计划和执行包装开销。
- [x] testkit 已提供有界响应式并发探针。
- [x] 在固定机器、数据库版本和数据量下完成首轮真实库基准并填写报告。
- [x] 首轮报告已记录吞吐、P50/P95/P99、错误率、负载器 CPU/堆和连接占用，没有只报告平均值。
- [x] 完成 MySQL `updateById` 发布后专项定位和显式事务对照；阶段观测确认主要成本在 SQL 执行及持久化提交，不在连接获取，固定 8 行显式事务的业务行吞吐约为单条自动提交的 3.60 倍。
- [ ] 证明关键场景达到 V1 性能门槛；未通过项为 MySQL 完整顺序中的单行更新尾延迟。停止无关容器后，原卷查询后更新 P99 仍回退 18.90%；全新独立卷短顺序三轮通过，但完整四场景三轮的更新 P95/P99 中位数仍回退 17.28%/45.66%。所有场景零错误且连接全部归还。原生 Linux 或独立磁盘交叉验证已按当前决定跳过并后置，性能门禁保持未通过，详细证据见 RC 性能报告。

## 发布结论

`v1.0.0` 按当前决定作为 GitHub 源码版本发布。功能、并发、连接回收、真实库兼容和上层 example 集成证据已经齐全；Oracle/SQL Server 已通过目标版本认证，但 V1 继续按预览支持发布。

MySQL `updateById` P99 历史性能门禁仍未放行，正式漏洞扫描则按明确决定跳过，因此不能把这个源码标签描述成“所有企业级性能与安全门禁全部通过”。P99 专项归因与显式事务对照已经结束，上述两项继续作为公开已知边界，不再列为待执行任务。
