# flying-orm v1.0.0 Hardening Redesign Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 将 flying-orm v1.0.0 一次收敛为简单易用、稳定安全优先，同时具备完整 Lambda-first 实体 API、框架无关的安全结构治理、真实低分配 SQL 计划、统一有界缓存和完整发布门禁的正式版本；原 v1.0.2 中属于 ORM 本体的规划全部前移到 v1.0.0。

**Architecture:** 保留 core → rdb → testkit/benchmark 的模块方向，删除旧公共 API 兼容包袱。先修数据库结果语义和安全默认值，再把缓存与映射改成实例级统一治理，随后收敛公共门面和内部职责，最后建立质量与真实数据库发布门禁并执行三轮审计。

**Tech Stack:** Java 21、Reactor 3.8、R2DBC SPI 1.0、Caffeine 3.2、JUnit 5、Maven、JMH、JaCoCo、SpotBugs、Checkstyle、OWASP Dependency Check。

**执行状态：** 2026-08-03 全量 code review 后重新打开。此前门禁通过，但仍存在默认 DDL、连接清理、
租户池连接、结构计划、Schema 多表批准和游标稳定性等语义缺口；以下方案 B 收口任务完成前不得标记发布就绪。
测试类注释按用户确认不纳入注释验收；生产类型、公开 API、配置和基础设施注释仍执行项目规范。

**三轮复查证据：**

1. 安全与正确性轮：检查执行上限、缓存语义、DDL 失效、回执事实、原生 SQL、ThreadLocal 和连接清理，并验证 ORM 本体不存在 Spring 依赖。
2. 架构与性能轮：检查实例级缓存、结构计划、批量分片/数组参数、紧凑行映射、Lambda 分层及发布制品；修复过期缓存注释、阻止算术更新值误入 insert，并收紧直接依赖声明。
3. 发布收口轮：重新生成 v1.0.0 API 基线，执行包含基线的干净全量 quality 构建、源码/Javadoc/依赖分析，并验证真实数据库 profile 缺配置即失败。

## Global Constraints

- 项目版本保持 `1.0.0`。
- flying-orm 本体不引入 Spring、不提供 Starter；Spring 适配只存在于上层服务或仓库外的独立项目。
- 默认 SQL 和 DDL 必须安全有界，只有显式 `unlimited()` 才解除普通 SQL 限制。
- 不保持旧公共 API 兼容，不保留废弃别名。
- 不使用 ThreadLocal 传递响应式业务上下文。
- 所有生产行为变更必须先看到聚焦测试按预期失败。
- 不创建 Git commit，不覆盖现有工作区修改。
- 所有中文 Javadoc 遵循 `wangr`、调整日期和 `v1.0` 规则。
- 原 v1.0.2 的 Lambda、实体元数据和框架无关 Schema 治理设计纳入 v1.0.0；Spring 自动装配明确不属于本仓库。
