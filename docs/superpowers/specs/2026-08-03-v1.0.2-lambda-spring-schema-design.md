# flying-orm v1.0.0 Lambda、Spring 集成与安全表结构同步设计

## 版本定义

原计划在 v1.0.2 提供的全部能力前移到 v1.0.0，并与 v1.0.0 的安全、缓存、性能和 API 收敛改造同时交付，不保留过渡 API。v1.0.0 必须同时满足以下目标，优先级从产品体验到运行质量依次为：

1. 简单、易用。
2. 稳定、安全优先。
3. 高性能、低延迟、高吞吐。

安全边界必须服务于易用性与运行质量，不能要求业务开发者记忆大量危险开关；易用性也不能绕过结构校验、数据范围、逻辑删除、乐观锁或执行保护。

## 目标

- flying-orm 的实体 API 全面支持类型安全 Lambda 字段引用。
- Repository、Operator、响应式、同步及 Spring 继承式 Service 共用一套 Lambda 元数据解析。
- Spring starter 默认扫描应用根包内全部 `jakarta.persistence.Table` 实体并注册泛型 Repository Bean。
- 当前实体通过继承式 Service 直接使用 CRUD；其他实体仍可显式注入对应 Repository。
- Spring 启动时可根据实体元数据自动建表并执行安全结构变更。
- 所有新增门面保持 R2DBC 主内核、参数绑定、背压、Scope、逻辑删除、乐观锁、观测和错误分类语义。

## 非目标

- 不删除动态表单所需的字符串字段 API。
- 不在 flying-orm 主项目引入 Spring 依赖。
- 不建立 JDBC 第二执行内核。
- 不替代 Flyway、Liquibase 或数据库发布平台。
- v1.0.0 不实现多实体 Join Lambda 与别名系统。
- 不允许启动过程自动执行删除字段、修改主键或不兼容类型转换等破坏性 DDL。

## 总体架构

### flying-orm 主项目

主项目提供纯 Java 能力：

- 可序列化实体字段引用与严格解析器。
- 实体字段引用到 `EntityFieldMetadata` 的缓存映射。
- Lambda 条件、选择、排序、分组和更新赋值 DSL。
- Repository 与类型化 Operator 的响应式、同步入口。
- 实体元数据到 `DynamicForm`、表结构差异、迁移计划和受控执行。

### Spring starter

Spring starter 只负责启动期发现和装配：

- 从 Spring Boot 应用根包扫描全部 `@Table` 实体。
- 预计算并注册实体元数据、动态表单和泛型 Repository Bean。
- 提供 `ReactiveOrmService<E>` 与同步对应门面。
- 在 Repository 对外可用前完成配置指定的结构校验或安全同步。
- 不复制主项目的 Lambda、Repository、SQL 渲染或 DDL 逻辑。

## Lambda-first 实体 API

### 字段引用契约

公开字段引用使用可序列化函数式接口，支持 JavaBean getter、布尔 `isXxx` getter 和 record accessor。解析器必须拒绝：

- 捕获外部变量的计算 Lambda。
- setter、静态方法、默认方法或任意业务方法。
- 所属实体类型不匹配的方法引用。
- 无法映射到持久化字段的方法。
- 不允许读写的字段进入对应操作。

解析结果必须经过 `EntityMetadata` 校验，最终使用映射后的数据库列名，不从方法名直接拼 SQL。

### 覆盖范围

实体 API 的以下入口增加 Lambda 重载：

- 条件：`where`、`and`、`or`、空值、集合、区间及自定义 term。
- 查询：`select`、`orderBy`、`groupBy`。
- 更新：`set`、数值增减及条件。
- 删除：条件、逻辑删除与显式物理删除。
- Repository、类型化 Operator、Reactive Service、Sync Service。

字符串重载继续保留，供动态表单、前端结构化条件和运行时字段使用。

### 目标业务写法

```java
@Service
public class DimensionUserService extends ReactiveOrmService<DimensionUserEntity> {

    private final ReactiveFormRepository<UserEntity> userRepository;

    public DimensionUserService(ReactiveFormRepository<UserEntity> userRepository) {
        this.userRepository = userRepository;
    }

    public Mono<Long> deleteRelation(String userId, String dimensionId) {
        return createDelete()
                .where(DimensionUserEntity::getUserId, userId)
                .and(DimensionUserEntity::getDimensionId, dimensionId)
                .execute();
    }
}
```

当前实体 Repository 由父类准备，不要求具体 Service 重复声明；操作其他实体时允许构造器显式注入对应 Repository。

## Spring 实体发现与 Repository 注册

- 默认扫描范围来自 Spring Boot 应用根包，不要求配置扫描包。
- 只发现应用范围内的 `@Table` 实体，不进行无边界第三方 classpath 扫描。
- 同一实体只解析一次；同一物理表存在不一致实体映射时启动失败。
- 为每个实体注册带准确泛型信息的响应式和同步 Repository Bean，使 Spring 能按 `ReactiveFormRepository<UserEntity>` 区分注入。
- Repository、元数据、动态表单均为可并发共享对象，不在每次业务调用中查询 `ApplicationContext` 或重复反射。
- 提供实体级排除能力，使只读视图或外部管理表可以注册 Repository 但不参与自动 DDL。

## 启动期安全表结构同步

### 模式

- `none`：不校验、不执行。
- `validate`：只校验，存在差异时启动失败。
- `plan`：生成可读计划，不执行。
- `safe-update`：自动建表并执行明确安全的增量变更。
- `reviewed`：只执行与批准指纹完全一致的受审计划。

starter 默认使用 `safe-update`：自动发现实体、创建缺失表并只执行明确安全的增量变更；遇到任何需要审核或破坏性差异时立即停止启动并输出计划。应用可显式切换为 `none`、`validate`、`plan` 或 `reviewed`，任何模式都不得绕过风险分类。

### 风险分类

`safe-update` 只允许：

- 创建不存在的表。
- 给现有表增加明确可安全执行的可空字段。
- 方言确认安全的注释和非破坏性元数据操作。
- 方言明确支持且满足锁超时约束的安全索引操作。

以下操作必须进入 `reviewed` 或直接拒绝：

- 增加非空字段、唯一约束、外键或可能长时间锁表的索引。
- 字段重命名、类型或长度变化、可空性收紧。
- 删除表、字段、索引、约束或修改主键。
- 方言无法证明安全、无法生成可靠执行计划的变更。

### 执行边界

- 多实例启动对同一数据库与 schema 使用数据库迁移锁。
- 获取锁后重新读取实际结构并重新生成计划，避免计划与执行之间的竞态。
- 批准指纹绑定数据库方言、当前结构、目标结构、迁移步骤和执行选项；任一变化使旧指纹失效。
- DDL 使用锁等待与执行超时，失败立即停止后续步骤。
- 迁移未完成前应用不能进入 Readiness 就绪状态。
- 执行完成后重新校验目标结构，并失效相关元数据缓存。
- 失败结果必须区分事务回滚、补偿建议、需要备份和不可逆操作，不承诺虚假回滚。

## 稳定性与错误模型

- Lambda 解析失败在生成 SQL 前抛出稳定错误，包含实体与属性路径，不暴露实现反射细节。
- 扫描冲突、Repository 泛型冲突、表映射冲突和结构风险均在应用接受流量前失败。
- DML 继续使用现有参数绑定、Scope、逻辑删除、乐观锁、超时、取消和异常分类。
- 启动迁移输出表、步骤、风险和计划标识，不输出数据库凭据或业务数据。
- Spring starter 不捕获或吞掉主项目稳定错误模型，只补充启动阶段上下文。

## 性能设计

- 实体扫描和结构同步只发生在启动阶段，不进入业务热路径。
- `EntityMetadata`、动态表单、Repository 和字段引用解析结果按实体类缓存。
- Lambda 首次解析后缓存；后续调用不得重复解析 `SerializedLambda` 或扫描反射成员。
- Repository 为单例且线程安全，Service 调用不进行逐请求 Spring Bean 查找。
- Lambda 门面不增加 SQL 数量、数据库往返或额外事务边界。
- 响应式入口保持非阻塞、背压和取消语义；同步入口只在最外层桥接。

性能验收包括：

- 缓存后的 Lambda 字段路径相对现有字符串元数据路径开销不超过 5%。
- 并发首次解析同一字段只产生一份缓存结果。
- 每次 CRUD 不产生额外元数据 SQL 或数据库往返。
- 新门面通过 JMH 回归基线及高并发 Repository 共享测试。

## 测试与完成标准

- JavaBean、boolean getter、record accessor、继承字段和注解列名 Lambda 测试通过。
- 非法 Lambda、跨实体字段、只读字段写入和未知字段稳定失败。
- Repository、Operator、Reactive/Sync Service 的查询、更新、删除行为一致。
- Spring 默认发现全部应用 `@Table` 实体，并能按泛型注入多个 Repository。
- Service 无需声明当前实体 Repository，但可显式注入其他实体 Repository。
- H2、MySQL、PostgreSQL、Oracle、SQL Server 的安全建表和差异计划契约一致。
- 多实例并发启动只允许一个迁移执行者，其余实例在锁释放后重新校验。
- 危险 DDL 不会在 `safe-update` 下执行，迁移失败不会让应用进入就绪状态。
- 性能门禁确认 Lambda 与 Spring 门面不破坏高性能、低延迟和高吞吐目标。
