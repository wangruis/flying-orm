# 2026-08-02 本机真实数据库性能基线

## 结论

本轮在固定 Docker MySQL 8.4.10、PostgreSQL 17.10 和 16 连接池下，完成查询、更新、ATOMIC 批量写入、
INDEPENDENT 分片写入共 8 个正式场景。所有场景都是零测量失败、零预热失败；每个数据库完成后，连接池借出数
和等待申请数都回到 0。本轮可以作为后续同机回归的第一份真实数据库基线，不能解释成跨机器吞吐承诺，
也不能代替候选版要求的至少三轮中位数。

## 复跑和判定

本轮先用本地认证资产的 Smoke 模式快速检查完整链路，再用 Formal 模式执行固定参数长跑。该编排和
PowerShell 入口不随源码仓库分发；复跑不能只照抄历史命令，必须同时锁定脚本版本、镜像、驱动和机器资源。

本轮脱敏原始证据保存在本机
`target/performance-results/20260801T163817Z-e471c9baadc6-formal`，该目录被 Git 忽略。正式候选版要在干净工作树、
相同镜像、驱动和机器资源下至少执行三轮，比较三轮中位数；任一轮出现业务错误、超时、连接未归还或非有限指标，
都不能用更高吞吐抵消失败。

## 指标边界

- CPU 是负载器 Java 进程的平均 CPU，不包含 Docker 数据库进程。
- 堆峰值来自 JVM heap memory pool，不等于 Java 进程 RSS，也不包含数据库内存。
- P50/P95/P99 是完成一次 ORM 操作的端到端客户端耗时；批量操作的一次代表 32 行。
- 本轮是初始基线，没有历史正式长跑可供判断 5% 告警或 10% 阻断。
- Docker 资源限制、后台负载、镜像、驱动、JDK 或 flying-orm 实现变化后，必须重新建立可比基线。

## RC 三轮结果

候选版三轮门禁结果见 [2026-08-02 RC 性能门禁](performance-rc-gate-2026-08-02.md)。三轮全部零错误且连接全部归还，
但 MySQL 单行更新的 P95/P99 中位数超过 10% 阻断线，因此当前不能把性能门禁标为通过。
