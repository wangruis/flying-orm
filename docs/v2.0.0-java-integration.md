# V2.0.0 纯 Java 接入示例

flying-orm 不依赖 Spring 或其他容器。应用只要提供 JDBC `DataSource`、R2DBC `ConnectionFactory`，以及当前外部事务的
连接上下文，就能使用和框架接入完全相同的 FormClient、Repository、Operator、Schema 与 Metadata。

## 原生 JDBC

没有外部事务时，最小装配只需要一个 `DataSource`：

```java
DataSource dataSource = ...;
FlyingOrmClients clients = FlyingOrmClients.builder(dataSource).build();

SyncFormClient forms = clients.syncForms();
SyncDatabaseOperator operator = clients.syncOperator();
```

纯 Java 应用自己管理事务时，可以用调用线程上下文把已经开始的事务交给 ORM。下面故意展示完整边界，实际项目通常会把
这段连接生命周期封装到自己的事务管理器中：

```java
ThreadLocal<JdbcTransactionContext> currentTransaction = new ThreadLocal<>();

FlyingOrmClients clients = FlyingOrmClients.builder(dataSource)
        .transactionParticipant(() -> Optional.ofNullable(currentTransaction.get()))
        .build();

// 动态数据源应在这里先选定主库，再从该主库取得事务连接。
try (Connection connection = dataSource.getConnection()) {
    connection.setAutoCommit(false);
    currentTransaction.set(JdbcTransactionContext.external(connection, "primary"));
    try {
        clients.syncForms().insert(writeSpec);
        clients.syncOperator().unsafeNativeSql(
                "update account set balance = balance - :amount where id = :id")
                .bind("amount", amount)
                .bind("id", accountId)
                .update();
        connection.commit();
    } catch (Throwable error) {
        connection.rollback();
        throw error;
    } finally {
        currentTransaction.remove();
    }
}
```

事务存在时，flying-orm 只关闭自己创建的 `PreparedStatement` 和 `ResultSet`，不会提交、回滚或关闭上面的连接。
`routingIdentity` 是已经选定的物理库标识；同一事务中请求另一个标识会在 SQL 前失败。因为事务连接来自主库，事务内查询
自然继续读主库，不再经过可能选择从库的连接工厂。

普通 CRUD 只需要连接参与能力。外部事务中的 `ATOMIC` 批量还需要上层适配器提供事务结束通知，才能把 `ENLISTED`
最终更新为 `COMMITTED`、`ROLLED_BACK` 或 `UNKNOWN`；这部分应接到上层事务管理器的同步回调，不能在业务代码中提前猜测。

## 原生 R2DBC

没有外部事务时只提供 `ConnectionFactory`：

```java
FlyingOrmClients clients = FlyingOrmClients.builder(connectionFactory).build();
ReactiveFormClient forms = clients.forms();
DatabaseOperator operator = clients.operator();
```

纯 Reactor 应用可以把外部事务连接放进 Reactor Context。下面的连接、提交和回滚仍由应用管理，flying-orm 只复用连接：

```java
R2dbcTransactionParticipant participant = R2dbcTransactionParticipant.reactorContext();
FlyingOrmClients clients = FlyingOrmClients.builder(connectionFactory)
        .transactionParticipant(participant)
        .build();

Mono<Long> transaction = Mono.usingWhen(
        Mono.from(connectionFactory.create()),
        connection -> Mono.from(connection.beginTransaction())
                .then(clients.forms().insert(writeSpec))
                .flatMap(rows -> Mono.from(connection.commitTransaction()).thenReturn(rows))
                .onErrorResume(error -> Mono.from(connection.rollbackTransaction())
                        .then(Mono.error(error)))
                .contextWrite(context -> R2dbcTransactionParticipant.bind(
                        context, R2dbcTransactionContext.external(connection, "primary"))),
        connection -> Mono.from(connection.close()));
```

响应式事务上下文只在订阅链中传播，不使用 `ThreadLocal`，也不允许在业务链中 `block()` 或手工 `subscribe()`。
Spring、Micronaut、Quarkus、Jakarta CDI 或自研容器的适配层只需要把各自已经绑定的连接转换成这里的
`JdbcTransactionContext` 或 `R2dbcTransactionContext`，ORM 行为不随容器改变。

## 同时装配两条执行链

应用同时提供两种连接能力时仍只创建一个客户端图：

```java
FlyingOrmClients clients = FlyingOrmClients.builder(dataSource, connectionFactory).build();
```

`clients.syncForms()`、`clients.syncOperator()` 和同步 Repository 只走 JDBC；`clients.forms()`、`clients.operator()` 和
响应式 Repository 只走 R2DBC。启动时会核对两边方言，不能把不同数据库类型静默装成一个运行环境。

## 接入其他 Java 容器

Micronaut、Quarkus、Jakarta CDI、自研容器和 Spring 使用同一个接入过程，容器适配层只做下面五件事：

1. 把自身配置系统中 `flying-orm` 前缀的值映射为 `FlyingOrmConfiguration`。
2. 把容器管理的 `DataSource`、`ConnectionFactory` 或两者放进 `FlyingOrmEnvironment`。
3. 把当前事务已经绑定的连接实现为 `JdbcTransactionParticipant` 或 `R2dbcTransactionParticipant`；没有事务时返回空。
4. 在动态多数据源场景把物理数据源清单交给启动校验，并保证事务开始前已经选定主库和稳定路由标识。
5. 调用一次 `FlyingOrmBootstrap.create(configuration, environment)`，再把得到的 `FlyingOrmClients` 及其 Repository、
   FormClient、Operator、Schema 和 Metadata 门面注册为容器单例。

适配层不能复制条件编译、SQL 渲染、批量、Scope、实体映射或错误处理，也不能在响应式容器里用线程池包装 JDBC 冒充
R2DBC。容器生命周期关闭时只关闭自己拥有的数据源和连接池；`FlyingOrmClients` 不夺取这些资源的所有权。
