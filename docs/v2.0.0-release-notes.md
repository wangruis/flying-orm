# V2.0.0 发布与迁移说明

V2.0.0 同时提供真正独立的 JDBC 同步内核和端到端非阻塞的 R2DBC 响应式内核。两条执行链共享动态表单、实体映射、条件 AST、Scope、SQL 渲染、方言、codec、错误模型和观测契约，但不共享连接，也不会互相桥接。

## 主要变化

- 同步入口直接使用 `DataSource`、`Connection`、`PreparedStatement` 和 `ResultSet`，不再等待 R2DBC Publisher。
- `FlyingOrmClients.builder(...)` 只保留三个使用入口：`ConnectionFactory`、`DataSource`、以及二者同时提供。
- FormClient、Repository、DatabaseOperator、Schema、Metadata、注册 SQL 模板和安全原生 SQL 均支持 JDBC/R2DBC 对应入口。
- 批量默认 `ATOMIC`，显式支持 `INDEPENDENT`；两条内核共享有界输入、分片结果、失败分类和 `UNKNOWN`
  结果语义。事务回执确认与安全重放仍由 R2DBC 提供，JDBC 使用业务幂等事实确认未知结果。
- 引入 flying-orm 自有实体注解与主键策略，覆盖数据库自增、序列、显式 ID、UUID、雪花 ID、字段填充、逻辑删除、乐观锁、枚举映射和默认排序。
- 上层事务存在时，ORM 使用上层绑定的同一物理连接，不重复提交、回滚或关闭；外部事务中的 `INDEPENDENT` 在 SQL 前拒绝。
- SQL 日志由上层日志系统管理。DEBUG 可输出安全 SQL、参数、耗时和行数；慢 SQL 与故障保留 WARN/ERROR 证据。
- 最终审查补齐了流式批量参数数组的即时快照、JDBC 生成键回调异常时的事务回滚，以及数据迁移、动态表单、实体枚举、Schema 重命名、SQL 模板注册和 SQL Server 注释目标失败说明的稳定脱敏；未改变稳定公共 API、SQL、方言或正常事务语义。

## 升级与接入要点

1. 同步代码必须提供 `DataSource`，响应式代码提供 `ConnectionFactory`；V2 不再提供 R2DBC 阻塞同步桥。
2. 实体改用 `com.flying.orm.core.annotation` 下的 `@TableName`、`@TableId`、`@TableField`、`@Version`、`@TableLogic`、`@EnumValue`、`@KeySequence` 和 `@OrderBy`。V2 不读取 Jakarta Persistence 实体注解。
3. 不再从 `FlyingOrmClients` 读取 renderer、dialect、sync metadata 或同步等待时长。业务直接使用 `forms()`、`operator()`、`repository(...)` 及对应 `sync*` 入口。
4. 原生 JDBC 没有等待 Publisher 的过程，因此删除了无实际作用的 `syncTimeout`。SQL 超时继续使用 `SqlExecutionOptions`，批量和 DDL 使用各自的统一执行保护。
5. 上层事务管理器通过 JDBC/R2DBC 事务参与 SPI 提供当前连接和最终完成信号。外部事务中的 `ATOMIC` 先返回 `ENLISTED`，最终结果以上层事务完成信号为准。

## 数据库与质量认证

- H2：JDBC/R2DBC 嵌入式契约闭环。
- 固定 V2 四库认证基线覆盖 MySQL 8.4.10、PostgreSQL 17.8 + pgvector 0.8.1、Oracle Free 23.26.0 和
  SQL Server 2022 CU22 GDR1；65 项四库用例连续复跑三轮，失败、错误和跳过均为 0。
- 发版源码在本机独立数据库上再次通过 MySQL 8.4 的 17/17 项认证，以及 PostgreSQL 18 的 18/18 项通用认证和
  1/1 项 schema/RLS 连接复用认证。当前本机 PostgreSQL 未安装 pgvector，向量能力仍以固定四库认证基线为准，
  不把未执行的扩展场景记为本次通过。
- MySQL 与 PostgreSQL：JDBC/R2DBC 各完成三轮固定参数性能认证，共 12 份报告、54 个场景轮次，错误、预热失败和结束时连接占用均为 0。
- 发布门禁：core 200、rdb 1266、testkit 84、benchmark 33 个测试通过；普通门禁中外部数据库场景按环境跳过。
  JaCoCo、SpotBugs、Checkstyle、依赖分析、Javadoc、源码包和发布产物检查通过。

详细结果见[数据库支持矩阵](database-support-matrix.md)、[V2.0.0 真实数据库与性能认证](database-certification-2026-08-08-v2.0.0.md)和[已知限制](known-limitations.md)。

## 获取方式

V2.0.0 当前不发布到远程 Maven 仓库。克隆源码后执行 `mvn clean install` 安装到本地仓库，应用依赖
`com.flying.orm:flying-orm-rdb:2.0.0`。Git 源码发布以 `v2.0.0` 标签为准。
