# V1.0.1 阶段 0 基线

这份基线只回答一个问题：V1.0.1 开始重构前，哪些行为必须原样保住。大型类拆分不能顺手改变 SQL、参数顺序、
事务、响应式资源生命周期、安全校验、错误分类或公开 API。

## 公开 API

core/rdb 的公开字节码签名由
`flying-orm-rdb/src/test/resources/api/v1.0.0-public-api.txt` 固定，SHA-256 为
`21CFB5AFFF0ED285D61686E78F61DF0A469A0DDBD097C0FA24DAD9A6CBFC70A7`。

`V1PublicApiBaselineTest` 会比较公开类型、字段、构造器和方法。普通测试只能读取快照，不能自动重写；确需改变公开
API 时，必须先说明必要性、唯一替代入口和迁移方式，再单独审查快照差异。

## 性能基线

V1.0.0 已有两类可复现基线：

- `performance-local-baseline-2026-08-01.md`：纯 Java 渲染、条件编译、映射、缓存和观测开销。
- `performance-database-baseline-2026-08-02.md`：MySQL/PostgreSQL 查询、更新、ATOMIC 和 INDEPENDENT。

这些数据是回归参照，不是 V1.0.1 的性能结论。首批拆分完成后使用相同 JMH 参数复跑相关场景；真实数据库认证仍
放在最终阶段。没有同机、同参数、稳定多轮数据时，只能说明行为保持，不能宣称吞吐提高或延迟下降。

## 首批拆分验收

2026-08-06 完成首批职责拆分后，生产类型规模如下：

| 类型 | 当前物理行数 | 说明 |
| --- | ---: | --- |
| `FormDataSqlRenderer` | 285 | 只保留稳定 DML 门面和结果解码入口，算法由查询、写入、批量及共享规则协作者承担 |
| `R2dbcSqlExecutor` | 297 | 只负责编排，连接会话、同连接序列、执行保护和观测已经分离 |
| `ObservedReactiveSqlExecutor` | 150 | 只负责装饰执行器，通用观测状态机由共享支持承担 |

同批运行 114 个聚焦契约测试，结果全部通过；core/rdb Checkstyle 为 0 个问题。这个结论只证明行为、公开 API
和代码规模门禁保持正确，不代替 JMH 与真实数据库认证。

## 未关闭项

- 首批拆分 JMH 已完成，结果见 `performance-v1.0.1-phase1-2026-08-06.md`；后续每个大型类治理批次继续复用同一门禁。
- 外部事务参与属于后续正式主线；本阶段只锁住 V1.0.0 已有事务和资源语义。

质量 profile 已启用 399 行和 29 方法硬门禁。尚未治理的存量大类以及声明式 `SchemaMetadata.Builder` 使用显式
Checkstyle 豁免；每完成一个类型就立即删除对应豁免。`FormDataSqlRenderer` 已移除文件长度豁免，只因稳定门面需要
保留既有 DML 方法而暂留方法数豁免，内部不再承载查询、写入或批量算法。
