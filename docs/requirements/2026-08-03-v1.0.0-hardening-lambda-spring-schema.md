# V1.0.0 稳定性加固、Lambda、Spring 与 Schema 自动化

## 决策

原 v1.0.2 规划全部前移到 v1.0.0，不保留旧 API 兼容负担。设计优先级固定为：简单易用、稳定与安全优先，其次在边界明确的前提下追求高性能、低延迟和高吞吐。

## 已落地范围

- 方言自动识别与 `FlyingOrmClients` 统一组装。
- 实体元数据约定模型、实例级有界缓存和 `DynamicForm` 自动生成。
- 全面的实体 getter Lambda 查询、投影、分组、排序、条件、更新、原子增减、删除及乐观锁。
- Spring Boot 可选 starter：应用根包实体发现、泛型 Repository 注册、继承式响应式/同步 Service。
- 启动期 schema 关闭、校验、创建和安全变更；不要求用户配置扫描包。
- 普通 SQL、DDL、批量写入、缓存和原生 SQL 逃生口的统一安全边界。
- SQL 结构计划、字段/实体映射缓存、批量数组绑定和流式分片、紧凑结果映射、Reactor Context 显式上下文。

## Schema 安全边界

- 默认关闭自动修改；开启后仍必须显式选择模式。
- 校验和创建可自动执行；变更必须经过迁移风险审核，破坏性变化默认拒绝。
- 多实例启动通过数据库锁协调，获取锁和执行 DDL 都有超时。
- 已开始执行的 DDL 无论成功、失败还是取消都会使相关元数据与计划缓存失效。
- 不扫描依赖库全世界的类路径，只从 Spring Boot 应用根包发现全部 `@Table` 实体，以避免无界扫描和意外接管第三方实体。

## 验收

最终以聚焦契约测试、完整 quality 门禁、release artifacts、API 基线和三轮全项目复查共同验收。真实外部数据库测试必须由显式 profile 和连接配置启用；未提供环境时不得宣称已执行。
